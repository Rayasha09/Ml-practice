# Практическая работа № 5. Классификатор и анализ метрик

**Вариант:** B

## Цель работы

Построить модель бинарной классификации, оценить её качество с помощью метрик и подобрать порог классификации с учётом стоимости ошибок.

## Используемый датасет

Breast Cancer Wisconsin из библиотеки `scikit-learn`.

- Количество наблюдений: 569.
- Количество признаков: 30.
- Количество классов: 2.
- Целевой класс 1 — злокачественная опухоль.
- Целевой класс 0 — доброкачественная опухоль.

## Используемые библиотеки и методы

- NumPy и Pandas — обработка данных.
- Matplotlib — визуализация.
- StandardScaler — масштабирование признаков.
- LogisticRegression — бинарная классификация.
- Scikit-learn Metrics — оценка качества модели.

## Этапы работы

1. Загрузка и анализ датасета.
2. Разделение данных на обучающую и тестовую выборки.
3. Масштабирование признаков и обучение Logistic Regression.
4. Получение вероятностей с помощью `predict_proba()`.
5. Построение матрицы ошибок.
6. Расчёт Accuracy, Precision, Recall и F1-score.
7. Построение ROC-кривой и Precision-Recall-кривой.
8. Расчёт ROC-AUC и PR-AUC.
9. Подбор порога классификации с учётом стоимости ошибок.
10. Сравнение результатов при порогах 0.5 и 0.24.

## Цена ошибок

Для учебного эксперимента приняты следующие условные стоимости:

- FN — 5, поскольку пропуск злокачественной опухоли считается более дорогой ошибкой.
- FP — 1, поскольку ложноположительный результат приводит к дополнительной проверке.

Формула стоимости ошибок:

`Cost = 5 × FN + 1 × FP`

Данные стоимости являются учебным допущением.

## Вывод

В ходе практической работы была обучена модель бинарной классификации Logistic Regression и выполнен анализ её качества.

Были рассчитаны основные метрики классификации, построены ROC- и Precision-Recall-кривые, а также матрицы ошибок.

Подбор порога позволил учитывать различную стоимость ложноположительных и ложноотрицательных ошибок. При пороге 0.24 минимальная стоимость ошибок составила 6.

Для окончательного сравнения необходимо учитывать результаты при стандартном пороге 0.5. В реальных задачах порог следует подбирать на валидационной выборке, а тестовую использовать для независимой оценки модели.
